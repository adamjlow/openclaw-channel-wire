# openclaw-channel-wire architecture

How the plugin is built and why. This is for engineers changing it; operators should read
[operations.md](operations.md). Every OpenClaw and Wire SDK behaviour described here was checked
against `openclaw@2026.9.6` and `@wireapp/wire-apps-js-sdk` 0.1.0 (plus PR #349) in September 2026.
Both SDKs are experimental or alpha, so re-check a symbol in the installed `.d.ts` before relying on
it. The repo skills in `.claude/skills/` set out that discipline.

## Targets

| Thing | Target | Notes |
|---|---|---|
| OpenClaw | `>=2026.9.6` | Peer dependency. `openclaw.compat.pluginApi` and `install.minHostVersion` match. |
| Node | `>=24.16 <25 \|\| >=26.1` | OpenClaw's range. The SDK's `engines: 22.22.1` only produces an `EBADENGINE` warning. |
| Wire SDK | 0.1.0 + #348/#349, vendored as `0.1.0-pr349` | Shipped via `bundleDependencies`, because `npm-pack:` installs can't resolve a nested `file:` dependency. Switch to the npm release and drop the bundling once it's published. |
| Host | Linux x86_64, glibc 2.38 or newer | CoreCrypto's native library needs this. The official OpenClaw image (bookworm, glibc 2.36) can't be used. |

## Module map

| Module | Role |
|---|---|

| `connection.ts`, `watchdog.ts`, `connection-state.ts` | SDK lifecycle, reconnect give-up detection, and the registry of live connections. |
| `sdk-runtime.ts` | **The only runtime import of the SDK.** Holds `WireAppSdk.create`, the events handler and `createWireApi`. |
| `wire-api.ts` | The plugin-owned `WireApi` interface and qualified-id helpers. Tests use fakes of it. |
| `inbound.ts`, `ingress-identity.ts` | Inbound queue, policy through the ingress resolver, dispatch and replies. |
| `outbound.ts`, `targets.ts` | Outbound adapter and the target grammar. |

Discovery and setup evaluate the entries and `channel.ts`. Those must not import the SDK or start
anything, and `import-safety.test.ts` enforces it.

## Identity, configuration and secrets

The plugin runs as a **Wire app**, not a user, registered by a team admin with
`scripts/register-app.mjs`. `channels.wire` is single-account, with every field at the channel root:
- `apiHost`, a plain `https://` URL;
- `apiToken` and `cryptoKey`, as SecretRefs or strings (`buildSecretInputSchema`, registered with
  `createSimpleChannelSecretContract`, mode `channel-only`);
- `dmPolicy`, `allowFrom`, `groupPolicy`, `groupAllowFrom`, `requireMention` and `assetPolicy`.

Secrets are resolved only when an account starts, with `resolveConfiguredSecretInputString`.
`inspectAccount` reports presence flags only. `resolveWireAccount` never throws: invalid config falls
back to safe defaults with `configured: false`, and the gateway refuses to start.

The crypto key must be 64 hex characters, decoded to 32 bytes. It is checked with a regex because
`Buffer.from(…, "hex")` silently drops invalid characters. The app's own id comes from
`manager.getApplicationQualifiedId()`.

Only one account is supported. The SDK is single-writer, and multiple instances in one process are
unsupported because its tsyringe container is process-global.

## State

SDK storage is `<state dir>/wire/<accountId>/`: `apps.db` plus `cryptography/`. It's passed as
`storagePath` (#348). The state dir comes from `runtime.state.resolveStateDir()` through the runtime
store, because `api` isn't available inside `startAccount`. The directory and the crypto key are one
unit: the backend rotates the token and the current one lives in `apps.db`, so the directory is the
live credential. One gateway per app identity.

OpenClaw's durable keyed stores, blob stores and ingress queue are refused to untrusted installs.
Dedupe and caches are therefore in-memory and bounded.

## Lifecycle

- `startAccount` calls
  `WireAppSdk.create(token, host, key, handler, logger, { storagePath, registerExitHandlers: false })`
  (#349; the gateway owns the process), then installs the backend connection listener and awaits
  `startListening()`. It then races `waitUntilAbort(abortSignal)` against a fatal promise. On exit it
  calls `stopListening()` and `close()`. `close()` clears the SDK's global container, so every run
  creates a fresh SDK.
- **OpenClaw owns restarts.** When a run ends, whether it resolved or rejected, the host restarts it
  with a backoff of 5 to 300 seconds (10 attempts, reset after 300 seconds of uptime). The plugin
  never sets `terminalDisconnect`.
- **Give-up detection.** SDK 0.1.0 stops reconnecting after 10 failures and only logs it. The SDK
  logger adapter matches that log line and raises a fatal error. As a backstop, a 5-minute watchdog is
  armed at start and on every disconnect, and a connect clears it. A failed first connect fires no
  disconnect event, which is why the watchdog is armed at start.
- The status probe reads `connection-state.ts` and never opens a second SDK.

## Inbound

SDK facts that shape this section:
- handlers are awaited, and there is no backend ack;
- a handler that throws loses its message, with no redelivery;
- live events run concurrently and can arrive out of order;
- the SDK's own dedupe is weak.

So:

1. The handler caches the message (for quoted replies), normalises it to plain data and returns.
2. Events are deduped by message id, then queued per conversation with OpenClaw's
   `createChannelRunQueue`.
3. The conversation kind comes from the SDK's local store (`getAllConversations`, cached). Unknown
   conversations are dropped.
4. Mentions count as either a Wire @mention whose `userId` equals the app's qualified id (domains
   compared) or a match on OpenClaw's mention patterns. The app's mention spans are stripped.
5. **Policy runs before anything else happens.** The plugin calls
   `core.channel.inbound.ingress.createResolver(…).message(…)` with the sender's qualified id as the
   subject. The identity declares `authentication: "asserted"`, a conservative claim. The call also
   passes `mentionFacts` for groups, `requireMention`, and
   `groupAllowFromFallbackToAllowFrom: true`. The host does **not** enforce DM policy by itself.
   The admission result decides what happens next:
   - `pairing-required` issues a challenge in the DM;
   - `skip` is a mention miss and is dropped quietly;
   - anything other than `dispatch` is dropped.
6. **Files** are fetched only after admission. The asset policy is checked first (MIME allowlist,
   declared size, remote data present), then the file is downloaded and its actual size checked, then
   it's saved with `core.channel.media.saveMediaBuffer` (the host owns retention and sanitises file
   names) and passed as `toInboundMediaFacts`. A rejection sends a short notice and starts no agent
   turn.
7. `resolveChannelInboundRouteEnvelope`, `buildContext` and `dispatch` run next. A DM peer is the
   sender, so sessions and bindings follow the person. A group peer is the conversation. Replies
   always go to the conversation key.

Known SDK limits: inbound quotes aren't mapped (`quotedMessageId` is never set), so a reply to one of
the app's messages can't count as an implicit mention. There are no typing indicators.

## Outbound

- **Target grammar:** a bare `<uuid>@<domain>` is a conversation. `user:<uuid>@<domain>` resolves to
  that person's 1:1 conversation through the local store. An optional `wire:` prefix is accepted.
- **Send results:** `sendText` and `sendMedia` return the real Wire message id and a
  `target: { kind: "conversation" }`. They throw `PlatformMessageNotDispatchedError` when offline
  (retryable) or when there's no 1:1 conversation (not retryable). Other failures propagate.
- **Quoted replies:** `TextMessage.createReply` is used when the original is cached (500 messages)
  and in the same conversation. Otherwise a plain message is sent. The reply mode is `off` in DMs
  and `first` in groups.
- **Files:** loaded with `core.media.loadWebMedia`, restricted to `getAgentScopedMediaLocalRoots`
  (or the host's `mediaLocalRoots`) and the size cap, then uploaded with `sendAsset`. Captions follow
  as text.
- **Chunking:** `textChunkLimit` is 8000, matching Wire clients' `MAXIMUM_MESSAGE_LENGTH`.

## Logging and privacy

Logs carry metadata only: kinds, counts, MIME types and policy names. The SDK logger drops debug
output, demotes info to debug, and passes only `Error.message` from metadata. `redact.ts` masks uuids
and email addresses in every logged error, SDK line and status `lastError`. Message text, file names,
tokens and keys are never logged.

## Testing

- **Unit tests (vitest):** the SDK is faked behind `WireSdkLike` and `WireApi`. `sdk-runtime.test.ts`
  mocks the SDK module itself, because the real one loads CoreCrypto (glibc 2.38 or newer).
  OpenClaw publishes no test helpers for third-party plugins.
- **`npm run smoke`:** installs the packed plugin into a fresh OpenClaw container, then runs
  `plugins inspect` and `plugins doctor`.
- **`npm run harness`:** a live gateway against a real Wire backend (see the README). The live checklist is in the README.
